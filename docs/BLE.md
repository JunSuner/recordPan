# recordPan BLE 协议（v1）

设备广播名为 `recordPan-XXXX`（XXXX 是蓝牙 MAC 地址的最后两个字节），广播包里带有下面的服务 UUID，App 可以按 UUID 过滤扫描结果。同一时间只能连接一台手机。所有多字节整数都是**小端序**。

## 服务

| 名称 | UUID | 属性 |
|---|---|---|
| recordPan 服务 | `6a2e0001-8b1f-4c3e-9d2a-7265636f7264` | — |
| Control 控制 | `6a2e0002-8b1f-4c3e-9d2a-7265636f7264` | Write / Write Without Response |
| Status 状态 | `6a2e0003-8b1f-4c3e-9d2a-7265636f7264` | Read / Notify |
| Files 文件列表 | `6a2e0004-8b1f-4c3e-9d2a-7265636f7264` | Notify |
| Audio 实时音频 | `6a2e0005-8b1f-4c3e-9d2a-7265636f7264` | Notify |
| Wi-Fi 热点信息 | `6a2e0006-8b1f-4c3e-9d2a-7265636f7264` | Read |

## Control：写入 1 字节命令

| 命令 | 值 | 说明 |
|---|---|---|
| START | `0x01` | 开始录音（已在录音时忽略） |
| STOP | `0x02` | 停止录音（没在录音时忽略） |
| MARK | `0x03` | 打一个标记（只在录音时有效） |
| LIST_FILES | `0x04` | 通过 Files 特征值返回录音文件列表 |
| WIFI_ON | `0x05` | 打开 Wi-Fi 热点和文件服务，见 [WIFI.md](WIFI.md) |
| WIFI_OFF | `0x06` | 关闭 Wi-Fi |
| DELETE | `0x07` + 文件名 | 删除录音和它的 `.json`（例如 `07 52 45 43 5F …` 即 `REC_…`）；正在录的文件不能删 |

蓝牙命令和设备上的实体按键走同一套处理流程，所以 LED、蜂鸣器、OLED 的反应都一样。

## Status：14 字节

订阅后每秒推送一次；开始、停止录音或打标记时会立即推送一次。也可以随时直接读取。

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | 协议版本，目前为 `1` |
| 1 | u8 | 状态：`0` 待机，`1` 录音中，`2` 存储不可用 |
| 2 | u16 | 本次录音的标记数 |
| 4 | u32 | 已录时长（毫秒），待机时为 0 |
| 8 | u32 | 剩余存储空间（KB） |
| 12 | i8 | 最近 20 ms 的输入峰值（dBFS），-96 表示静音 |
| 13 | u8 | flags：bit 0 = Wi-Fi 已打开 |

## Wi-Fi：热点信息

读取后得到三行 UTF-8 文本：SSID、密码、IP，例如 `recordPan-FF92` / `k3mx…` / `192.168.4.1`。密码每次开机随机生成。

## Files：文件列表

先订阅这个特征值，再写入 `LIST_FILES` 命令。设备会为每个音频文件（`.opus` / `.wav`）推送一条通知：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u32 | 文件大小（字节） |
| 4 | UTF-8 | 文件名，例如 `REC_0009.opus`，长度为通知长度减 4 |

列表推送完后，再推送一条只有 4 字节、内容为 `FF FF FF FF` 的通知，表示列表结束。每个录音还有一个同名的 `.json` 元数据文件，格式见 [firmware/README.md](../firmware/README.md)，通过 Wi-Fi 和录音一起下载（见 [WIFI.md](WIFI.md)）。

## Audio：实时音频流

订阅后，录音期间设备会推送 Opus 数据：16 kHz 单声道，每包 20 ms，和存进文件的是同一份编码数据。每条通知最多装 3 个包，也就是 60 ms 音频：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u16 | 第一个包的帧序号（从录音开始计数，每 20 ms 加 1，超过 65535 后回绕） |
| 2 | u8 | 包的数量 N |
| 3 | — | 重复 N 次：u8 长度 L，后面跟 L 字节的 Opus 包 |

- 帧序号不连续说明中间有包丢了，接收端应该用丢包补偿或静音补上。
- 需要 ATT MTU 至少 100 左右，iOS 默认协商到 185 以上，满足要求。
- 链路拥塞时，设备会直接丢弃来不及发送的包。录音文件本身不受影响。
